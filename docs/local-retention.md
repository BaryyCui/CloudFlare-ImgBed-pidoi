# Docker 本地存储定时清理

## 使用范围

管理员登录后打开 **系统设置 → 定时清理**（`/systemConfig#retention`）。

此功能仅用于 Docker 运行方式下的本地存储。范围是 `/app/data/r2/videos/` 及其子目录，包括其中的图片、视频和音频。实际宿主机目录由 Docker 数据卷决定，例如 `/opt/cloudflare-imgbed-pidoi/data/r2/videos/`。

| 设置 | 默认值 |
| --- | --- |
| 自动清理 | 关闭 |
| 保留天数 | 7 天 |
| 每日执行时间 | 03:00 |
| 时区 | Asia/Shanghai |
| 目录 | videos/ 及子目录 |

配置独立保存，升级不会自动打开清理开关，也不会覆盖其他图床设置。删除后的链接会失效，清理日志不是素材备份。

## 启用与预览

1. 设置保留天数及每日时间，保存配置。
2. 点击预览，核对截止时间、匹配数量、预计释放容量和素材样例。
3. 打开自动清理并保存后，后台显示下一次计划时间。首次执行为下一个计划时刻，保存本身不会立即删除文件。
4. 需要立即清理时，先预览，再明确确认本次范围。修改设置后需重新预览。

保留期按连续 24 小时计算。例如运行时间为上海时间 10 月 29 日 03:00、保留 7 天，截止时间即 10 月 22 日 03:00。上传记录和本地文件修改时间均须早于本次截止时间才会进入清理。

## 执行与保护

- 直接从真实文件记录分批筛选，不依赖可能滞后的管理页面列表。
- 定时和手动任务共用持久执行锁，防止重复运行。
- 一次任务固定配置、截止时间和候选版本；文件被替换、元数据变化或正在上传时跳过。
- 其他目录、远端存储、符号链接和临时分片不在清理范围。
- 文件记录、对应导入重放记录和索引可见性共同处理；历史索引操作不能使已清理文件重新显示。
- 运行记录展示删除数量、释放容量、跳过数量和失败原因。服务重启后可检查中断任务的恢复状态。

## 运维说明

持久化 `/app/data` 数据卷。配置、执行记录和恢复状态保存在图床自己的 SQLite 数据库中。

Docker 外的运行方式会明确显示不支持自动清理。清理功能不会连接或修改 new-api 的数据库、用户任务、账单或余额。

使用单个 Docker / Node 进程写入本地素材目录。活动上传保护不适用于多个独立进程共同覆盖同一目录；不要把同一个素材卷同时挂给多个写入实例。

本地开发和验收可设置 `IMGBED_DATA_DIR` 为独立的临时目录。未设置时仍使用原来的 `data/` 目录，不改变现有 Docker 数据卷路径。

部署后先保持开关关闭，预览确认范围后再启用。定时清理可以控制持续增长，但不能替代磁盘容量告警和重要素材的异地备份。
